## Overview

This week completed a full rebuild of the Perch-Hoplite passive acoustic

## Critical Finding: Low-Amplitude Normalization Bug (July 9 2026)

### Discovery
Direct comparison of the PyTorch port against Google's live TF Perch 2.0
model (Kaggle SavedModel, Colab A100) revealed that the port diverged from
TF on real MARS hydrophone audio.

MARS hydrophone recordings have typical peak amplitude 0.0015–0.003 — far
below normal audio levels. Perch internally peak-normalizes each 5-second
window to 0.25 before the log-mel frontend. At MARS amplitude levels, this
amplifies the signal by ~125×, causing float32 arithmetic to diverge in mel
bins near the `1e-5` log floor:

| Raw clip peak | cos(port, live TF) |
|---|---|
| 0.32 (normal audio) | 0.9998 |
| 0.0024 | 0.9472 |
| 0.0006–0.0007 (MARS typical) | 0.43–0.55 |

All 120 windows in a representative MARS file were below peak 0.005 — the
**entire MARS dataset was in the divergence zone**.

### Fix
Pre-normalize each 5-second window to peak 0.25 before embedding. This is
idempotent with Perch's internal normalization — the canonical embedding is
unchanged, but the frontend arithmetic stays in a numerically stable range.

**Verified:** cos 1.00000 vs live TF on all tested MARS windows after fix.

### Impact
All embeddings produced before July 9 2026 were non-canonical. They have
been regenerated. Annotations (filename + offset references) were preserved.
Classifier results are similar — April 13 2018 orca count shifted from
295 to 286–291 (−1.4% to −3%).

See: `docs/FINDINGS_2026-07-09_tf_parity_and_lowamp_fix.md`

## Infrastructure Changes

### New Permanent Directory Structure
All pipeline data moved from `duane_scratch` (implied temporary) to a
permanent location:

```
/mnt/PAM_Analysis/perch-hoplite/   ← permanent (new)
    db/          — embedding databases
    models/      — trained classifiers
    results/     — inference CSVs and plots
    logs/        — embedding and inference logs
    provenance/  — label and training JSON records

/mnt/PAM_Analysis/perch_weights/   ← Perch V2 weights (ONNX-extracted)
    weights.npz
    graph_manifest.json
```

Old location (`duane_scratch/perch_hoplite/`) kept read-only for reference.

### Code Refactoring (`src/` modules)
`phase2_classify.py` (2,500 lines) was modularized into:

| Module | Contents |
|---|---|
| `src/spectrogram.py` | 4-mode spectrogram (linear, mel, perch, pcen) |
| `src/audio.py` | Audio encoding + 30s context windows |
| `src/torch_model.py` | TF mock injection + model loading |
| `src/train.py` | PyTorch linear classifier training |
| `src/infer.py` | Inference with write-to-tmp NFS fix |
| `src/review.py` | Gradio labeling GUI |
| `src/paths.py` | Canonical path definitions with duane_scratch fallback |

### Inference NFS Fix
Rewrote inference to write CSV to `/tmp` first then copy to NFS in one
operation. Eliminates the `ThreadPoolExecutor` NFS hang that caused
inference to appear frozen for 30+ minutes after completion.

### New Features
- `--spectrogram-type linear|mel|perch|pcen` — spectrogram mode selection
- 30-second context windows pre-computed at Gradio startup (no waiting)
- Auto-delete of stale CSV before inference (prevents append corruption)
